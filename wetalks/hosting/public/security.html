Security

Security

How WeTalks protects your conversations, and where the limits are. We prefer to be honest and specific.

The short version

Everything you send is encrypted on your phone before it leaves it. Our servers store and forward scrambled data. The keys that unlock it stay on your device, so we can't read your chats, photos, voice notes or files, even if we wanted to or were asked to.

How it works

  • Keys. Each phone makes its own X25519 key pair. The private key is wrapped by the Android Keystore and never uploaded. The public key is published so contacts can start a chat.
  • Chats. Two people derive a shared secret from their keys and use AES-256-GCM to encrypt every message. Groups use a random group key that is delivered to each member encrypted for them, and replaced when a member is removed.
  • Files. Each file gets its own random 256-bit key and is encrypted in 1 MB pieces, so tampering is detected. The key travels inside the encrypted message. Our file server only sees encrypted bytes.
  • Calls. Voice and video travel peer-to-peer (WebRTC, DTLS-SRTP). The call setup messages are encrypted with your chat key.
  • Notifications. A push only says "something new" and which chat. It never contains a name or message text.

What we protect on the servers

  • Sign-in checked everywhere. Every request to our media and developer servers carries a Firebase sign-in token that is verified against Google's public keys.
  • Rules, not trust. Who can read or write a chat is enforced by database security rules that we test automatically (30+ checks), not by application code that could be bypassed.
  • Files are stored outside the web root under random 128-bit names and are only released after the server confirms you belong to that chat.
  • Limits. File type and size limits, per-user quota and rate limits on uploads, and rate limits on every API call.
  • No admin keys on web servers. The developer API signs in as an ordinary, tightly-limited account. Powerful credentials are never stored on the website server.

What you should know (the honest part)

Service messages are different. Codes and alerts from apps that use the developer API are generated by their servers, so they are protected in transit and in storage but are not end-to-end encrypted. They are shown in a separate inbox, labelled with the app's name, and you can switch them off or block any app.
  • Metadata. To deliver messages we need to know who is talking to whom and when, plus your account details. We don't sell it or use it for ads.
  • Lost phone, lost keys. Because only your device holds the keys, a reinstall can't read old chats unless you made a key backup. Create one in Settings → Privacy & security, protected by a passphrase only you know.
  • Translation & speech. Translating a message or transcribing a voice note sends that one piece of text or audio to an online engine when you ask for it. Nothing is sent unless you tap.
  • Verify safety numbers with a contact if you need certainty that nobody is in the middle.
