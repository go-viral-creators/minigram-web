Overview

The WeTalks API lets your server send a message or a verification code to a person who uses WeTalks. Messages appear in the person's Service messages inbox in the app, labelled with your app's name, and trigger a notification.

Base URLhttps://wetalks.fireclashpro.com/api/v1
FormatJSON over HTTPS. Send Content-Type: application/json.
AuthAPI key in the Authorization header
RecipientA WeTalks username, with or without @
Service messages are delivered to the person's inbox, not into an end-to-end encrypted chat, because your server (not their phone) creates the content. See Security.

Authentication

Create an app in the developer portal, then create an API key. Keys start with wt_live_ and are shown once. Send the key on every request:

Authorization: Bearer wt_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Keep keys on your server. Never put one in a mobile app or website code. If a key leaks, revoke it in the portal and it stops working immediately. Test the key with:

GET/ping

Checks that your key works and returns your app.

curl https://wetalks.fireclashpro.com/api/v1/ping -H "Authorization: Bearer $WETALKS_KEY"

Response

{
  "ok": true,
  "app": { "id": "app_1a2b3c4d5e6f", "name": "Acme Shop", "verified": false }
}

Send a message

POST/messages

Delivers a message to one person. They get a notification and can find it in Service messages.

FieldTypeDescription
tostring, requiredWeTalks username, e.g. @asha
textstring, requiredThe message, 1 to 500 characters
titlestringShort heading, up to 60 characters
kindstringinfo (default), alert or followup
linkstringOptional https:// link, up to 200 characters. People are asked before it opens.
curl -X POST https://wetalks.fireclashpro.com/api/v1/messages \
  -H "Authorization: Bearer $WETALKS_KEY" \
  -H "Content-Type: application/json" \
  -d '{"to":"@asha","title":"Order shipped","text":"Your order #1234 is on the way","kind":"alert","link":"https://shop.example.com/o/1234"}'
const res = await fetch("https://wetalks.fireclashpro.com/api/v1/messages", {
  method: "POST",
  headers: { "Authorization": `Bearer ${process.env.WETALKS_KEY}`, "Content-Type": "application/json" },
  body: JSON.stringify({"to":"@asha","title":"Order shipped","text":"Your order #1234 is on the way","kind":"alert","link":"https://shop.example.com/o/1234"}),
});
console.log(res.status, await res.json());
import os, requests
r = requests.post("https://wetalks.fireclashpro.com/api/v1/messages",
    headers={"Authorization": "Bearer " + os.environ["WETALKS_KEY"]},
    json={"to":"@asha","title":"Order shipped","text":"Your order #1234 is on the way","kind":"alert","link":"https://shop.example.com/o/1234"})
print(r.status_code, r.json())
$ch = curl_init("https://wetalks.fireclashpro.com/api/v1/messages");
curl_setopt_array($ch, [CURLOPT_POST => true, CURLOPT_RETURNTRANSFER => true,
  CURLOPT_HTTPHEADER => ["Authorization: Bearer " . getenv("WETALKS_KEY"), "Content-Type: application/json"],
  CURLOPT_POSTFIELDS => '{"to":"@asha","title":"Order shipped","text":"Your order #1234 is on the way","kind":"alert","link":"https://shop.example.com/o/1234"}']);
echo curl_exec($ch);

Response

{
  "id": "71144c0c9e261f99",
  "status": "delivered",
  "to": "@asha"
}

Use followup for things the person asked for (a reminder, a status update). Do not send promotions.

Verification codes (OTP)

WeTalks creates the code, delivers it to the person and checks it for you, so you never have to generate, store or protect the code yourself.

  1. Your user types their WeTalks username in your app.
  2. You call POST /otp. WeTalks sends a code to their inbox and returns an otp_id.
  3. The user types the code into your app.
  4. You call POST /otp/verify with the otp_id and the code. If valid is true, they own that account.

POST/otp

Sends a one-time code. The response never contains the code.

FieldTypeDescription
tostring, requiredWeTalks username
lengthinteger4 to 8 digits, default 6
ttlintegerSeconds the code is valid, 60 to 600, default 300
curl -X POST https://wetalks.fireclashpro.com/api/v1/otp \
  -H "Authorization: Bearer $WETALKS_KEY" \
  -H "Content-Type: application/json" \
  -d '{"to":"@asha","length":6,"ttl":300}'
const res = await fetch("https://wetalks.fireclashpro.com/api/v1/otp", {
  method: "POST",
  headers: { "Authorization": `Bearer ${process.env.WETALKS_KEY}`, "Content-Type": "application/json" },
  body: JSON.stringify({"to":"@asha","length":6,"ttl":300}),
});
console.log(res.status, await res.json());
import os, requests
r = requests.post("https://wetalks.fireclashpro.com/api/v1/otp",
    headers={"Authorization": "Bearer " + os.environ["WETALKS_KEY"]},
    json={"to":"@asha","length":6,"ttl":300})
print(r.status_code, r.json())
$ch = curl_init("https://wetalks.fireclashpro.com/api/v1/otp");
curl_setopt_array($ch, [CURLOPT_POST => true, CURLOPT_RETURNTRANSFER => true,
  CURLOPT_HTTPHEADER => ["Authorization: Bearer " . getenv("WETALKS_KEY"), "Content-Type: application/json"],
  CURLOPT_POSTFIELDS => '{"to":"@asha","length":6,"ttl":300}']);
echo curl_exec($ch);

Response

{
  "otp_id": "otp_4e763ad9a89da06026f5",
  "to": "@asha",
  "length": 6,
  "expires_at": "2026-11-06T11:23:51+00:00"
}

POST/otp/verify

Checks a code. A code works once, expires after its time-to-live and is locked after 5 wrong tries.

FieldTypeDescription
otp_idstring, requiredThe id returned by /otp
codestring, requiredThe digits the user typed
curl -X POST https://wetalks.fireclashpro.com/api/v1/otp/verify \
  -H "Authorization: Bearer $WETALKS_KEY" \
  -H "Content-Type: application/json" \
  -d '{"otp_id":"otp_4e763ad9a89da06026f5","code":"123456"}'
const res = await fetch("https://wetalks.fireclashpro.com/api/v1/otp/verify", {
  method: "POST",
  headers: { "Authorization": `Bearer ${process.env.WETALKS_KEY}`, "Content-Type": "application/json" },
  body: JSON.stringify({"otp_id":"otp_4e763ad9a89da06026f5","code":"123456"}),
});
console.log(res.status, await res.json());

r = requests.post("https://wetalks.fireclashpro.com/api/v1/otp/verify",

Response

{ "valid": true }

// or
{ "valid": false, "reason": "invalid" }   // invalid | expired | used | too_many_attempts

Usage

GET/usage

Today's counts and your daily limits.

curl https://wetalks.fireclashpro.com/api/v1/usage -H "Authorization: Bearer $WETALKS_KEY"

Response

{
  "date": "2026-11-06",
  "messages": { "used": 12, "limit": 200 },
  "otps": { "used": 4, "limit": 100 },
  "errors": 1
}

Errors

Errors use standard HTTP status codes and a JSON body:

{ "error": { "code": "user_not_found", "message": "no WeTalks user with that username" } }
HTTPcodeMeaning
401—Missing, malformed, wrong or revoked API key
403recipient_not_acceptingThe person turned off service messages or blocked your app. Don't retry, ask them to enable it.
404user_not_foundNo WeTalks user with that username
422invalid_text, invalid_kind, invalid_link, invalid_length, invalid_ttlThe request body failed validation. The message explains what to fix.
429daily_limit, recipient_limit, recipient_busyA limit was reached. Check the Retry-After header.

Security tips

  • Store the key in an environment variable or secret manager, never in source control or client code.
  • Use one key per environment and revoke keys you no longer need.
  • Always verify codes on your server, never in the browser or app.
  • Tell users never to share codes, and never ask for a WeTalks password.
  • Rate limit the "send code" button in your own product to avoid annoying people.
